# TUI Visibility Comparison — looplane vs. reference coding agents

Context: looplane's pipeline is SDK query() (scripts/claude-agent-session.mjs) →
sidecar frame protocol → Python (src/looplane/claude_agent_session.py) →
TUI (src/looplane/terminal/projection.py). Known frame types: `ready`,
`turn_accepted`, `approval_accepted`, `text_delta`, `tool_started`,
`tool_completed`, `action_preview_updated`, `approval_requested`,
`context_usage_updated`, `runtime_model_updated`, `turn_completed`, `fatal`.

## 1. How reference agents surface "thinking"/reasoning

| Agent | Event/type carrying thinking | Rendering | Persisted? |
|---|---|---|---|
| **pi-mono** | Assistant message `content` blocks of `type: "thinking"` (Anthropic-native) | `pi-mono/packages/coding-agent/src/modes/interactive/components/assistant-message.ts#thinkingBlocks` — rendered as its own Markdown section in a dedicated `thinkingText` theme color; can be collapsed to one static "hidden thinking" label (`hiddenThinkingLabel`) via a settings toggle (`src/core/settings-manager.ts` has `modelThinkingLevels`/`thinkingBudgets`) | Yes, part of the message content array (session transcript) |
| **opencode** | Internal normalized part `type: "reasoning"`, mapped 1:1 to/from Anthropic's `thinking`/`thinking_delta` in `opencode/packages/llm/src/protocols/anthropic-messages.ts#lowerThinking` (streaming via `Lifecycle.reasoningDelta`/`reasoningEnd`, line ~686-776); OpenAI Responses reasoning summaries handled separately (bolded-title parsing) | `opencode/packages/tui/src/context/thinking.ts#useThinkingMode` — explicit `ThinkingMode = "show" \| "hide"`, **defaults to "hide"**, user cycles via slash command; migrates a legacy `thinking_visibility` boolean | Yes, stored as a `reasoning` part in the transcript regardless of display mode |
| **codex** | Protocol events `AgentReasoning`, `AgentReasoningRawContent` (true raw CoT when the model/provider exposes it), `AgentReasoningSectionBreak` — `codex/codex-rs/protocol/src/protocol.rs#AgentReasoningEvent` (~L2524) | `codex/codex-rs/tui/src/chatwidget` renders reasoning as history cells with streaming deltas (see snapshot tests `reasoning_delta_restores_recreated_status_indicator`, `final_reasoning_then_message_without_deltas_are_rendered`) | Yes, via rollout/thread history (`app-server-protocol/src/protocol/thread_history.rs` handles `AgentReasoning*` payloads) |
| **claude-code-source** | Native Anthropic `thinking` / `redacted_thinking` content blocks, `thinkingConfig` passed into the query (`src/query.ts` ~L662) | `src/components/Message.tsx` (~L524-612): renders `thinking` blocks in a distinct style; **only the last thinking block in a run is expanded by default** (`isLastThinking`/`lastThinkingBlockId`), everything earlier collapses; `redacted_thinking` renders a "thinking hidden for safety" placeholder | Yes, part of message content; verbose-mode toggle controls expansion, not existence |

| **oh-my-pi (omp)** | Native `type: "thinking"` content block (`packages/ai/src/types.ts`), PLUS a unique **cross-provider healing layer** for models that leak reasoning into the visible text channel instead of a structured part — `packages/ai/src/utils/leaked-thinking-stream.ts#wrapLeakedThinkingStream` live-splits leaked fences (`` ```thinking ``, `<think>`, Gemma/Harmony channels) out of the text stream into proper thinking blocks as deltas arrive; gated off only for official first-party Anthropic/OpenAI endpoints (`stream.ts#healLeakedThinking`) which already return structured thinking | `packages/coding-agent/src/modes/components/assistant-message.ts` — live "thinking pulse" (animated dots) rendered in place of a hidden thinking block while it streams, with a **tokens/sec speed badge** (`#thinkingTokens`, `#thinkingRateLive`); `hideThinkingBlock`/`proseOnlyThinking` settings (`config/settings-schema.ts:1381,1391`); per-role **thinking budget levels** (`minimal`→`max`, `thinkingBudgets.*` in tokens, `settings-schema.ts:6006-6016`) plus an `AUTO_THINKING` auto-classifier (`auto-thinking-classifier.test.ts`) that picks a level per turn | Yes, `thinking` content blocks persist in session content array like any other block |

**Common pattern across all four (five incl. omp):** thinking is a first-class content-block/part type carried end-to-end through the protocol, always persisted, and its *visibility* (not its transport) is what's user-toggleable — usually defaulting to collapsed/hidden, never to "dropped entirely." looplane's gap is one layer earlier: the SDK call itself doesn't request `thinking`, and even if the model emitted it, the sidecar's `content_block_delta` handler only matches `delta.type === "text_delta"` and the non-streaming fallback only matches `block.type === "text"`/`"tool_use"` — a `thinking`/`thinking_delta`/`redacted_thinking` block is silently discarded before it ever becomes a frame.

## 2. Other categories reference agents surface that looplane's frame set does NOT

- **stop_reason granularity (max_tokens / refusal / end_turn distinction).** looplane's `turn_completed` only has `status: completed|failed|interrupted` and a generic `"Claude turn failed"` string (`scripts/claude-agent-session.mjs:505-529`) — no `stop_reason` field is read from the SDK result at all (`grep stop_reason` → no hits). pi-mono explicitly branches UI on `message.stopReason === "length"/"aborted"/"error"` (`assistant-message.ts:177-190`) so a user can tell "truncated by max tokens" from "you interrupted it" from "provider error."
- **Partial/streaming tool-call JSON as it's being built.** Anthropic's `input_json_delta` stream events exist and are consumed by pi-mono's/opencode's Anthropic client code (`pi-mono/packages/ai/src/api/anthropic-messages.ts`, `opencode/packages/llm/src/protocols/anthropic-messages.ts`) to show a tool call's arguments filling in live. looplane's sidecar only branches on `delta.type === "text_delta"` (`scripts/claude-agent-session.mjs:493`) — an `input_json_delta` is invisible; `tool_started` only fires once the full tool_use block is complete, carrying a truncated `summary` string, never the raw structured input (`ensureAction`, `scripts/claude-agent-session.mjs:327-345`).
- **Retry / rate-limit backoff notices.** codex has a dedicated `RateLimitSnapshot`/`RateLimitReachedType` in its protocol (`codex/codex-rs/protocol/src/protocol.rs:2283-2311`) surfaced in the TUI so the user sees "backing off, rate limited" instead of a silent stall. looplane's sidecar has no retry/backoff logic or event at all — a rate-limit from the SDK would presumably just surface as a generic `fatal` (or hang), with no user-visible distinction from any other failure.
- **Fine-grained permission/sandbox denial reason (not just user's own allow/deny).** codex threads sandbox-level denial reasons through `app_server_session.rs`/`ide_context` (distinct from a human's approval decision). looplane's `approval_requested`/`approval_accepted` (`scripts/claude-agent-session.mjs:394-416`) only model the *user's* allow/deny choice — there's no channel for "the sandbox itself blocked this regardless of what you'd have approved," because looplane doesn't appear to run a lower-level OS sandbox in this sidecar at all (tools are Read/Glob/Grep/Bash/Edit/Write gated purely by the approval hook).
- **Cache-creation tokens broken out separately from reasoning tokens.** Partially covered (see below) but note `reasoning_output_tokens: 0` is hardcoded in `inclusiveUsage` (`scripts/claude-agent-session.mjs:112-131`) — a placeholder for a stat the pipeline can never populate since thinking isn't requested/parsed at all.

## 3. Categories looplane ALREADY covers — do not misreport as gaps

- **Context window fill / token usage** → `context_usage_updated` frame, built from `inclusiveUsage()` (`scripts/claude-agent-session.mjs:112-132`) and `contextTelemetryForResult()` (`:164-184`). Includes `input_tokens`, **`cached_input_tokens`** (cache read), `output_tokens`, `total_tokens`, `context_window`. So basic cache-read stats and context-window percentage are already plumbed through — only cache-*creation* tokens are folded into `input_tokens` rather than broken out, and there's no cost/pricing display, which may or may not matter.
- **Model/provider switch notices** → `runtime_model_updated` frame (`updateRuntimeModel`, `scripts/claude-agent-session.mjs:145-151`), fired whenever the SDK reports a different `message.message.model`.
- **Diff preview before apply** → `action_preview_updated` frame + `proposed_changes` on `approval_requested` (`scripts/claude-agent-session.mjs:401`) — this is looplane's equivalent of claude-code-source's `StructuredDiff`/`FileEditToolDiff` components; already wired to `src/looplane/terminal/projection.py` for rendering before the user approves.
- **Tool call activity (start/complete, path, summary)** → `tool_started`/`tool_completed` frames — coarser than reference agents' live-arg streaming, but the category itself (a tool ran, on what, with what result) is covered, just not at streaming granularity.
- **Sub-agent/Task delegation** → deliberately *not* a gap: `disallowedTools: ["Agent", "Task", ...]` in the SDK query options (`scripts/claude-agent-session.mjs:480`) and the sidecar throws `"subagent output is forbidden"` (`:501`) — looplane intentionally forbids subagents in this session type, so there's nothing to surface.
- **MCP/server tools** → also deliberately forbidden (`mcpServers: {}`, `strictMcpConfig: true`, throws on `mcp_tool_use`/`server_tool_use`) — not a gap, a design constraint.
